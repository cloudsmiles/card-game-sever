# QCard Frontend - 测试指南

## 快速开始

### 1. 启动服务

#### 启动后端服务器
```bash
cd card-game-server/backend
go run main.go
```
后端将运行在 `http://localhost:8080`

#### 启动前端开发服务器
```bash
cd card-game-server/frontend
npm run dev
```
前端将运行在 `http://localhost:3000`

### 2. 基础功能测试

#### 测试 1: 连接功能
1. 打开浏览器访问 http://localhost:3000
2. 输入昵称（例如：玩家1）
3. 点击"进入大厅"
4. **预期结果**: 成功连接并跳转到大厅页面

#### 测试 2: 创建房间
1. 在大厅页面点击"创建房间"
2. 选择游戏类型（斗地主）
3. 点击"创建"
4. **预期结果**: 自动跳转到房间页面，显示房间信息

#### 测试 3: 多人加入房间
1. 打开第二个浏览器标签页
2. 输入不同昵称（例如：玩家2）连接
3. 在大厅中找到刚创建的房间
4. 点击"加入房间"
5. **预期结果**: 成功加入房间，两个标签页都能看到玩家列表更新

#### 测试 4: 准备功能
1. 在房间页面点击"准备"按钮
2. **预期结果**: 
   - 按钮变为"取消准备"
   - 玩家列表中显示"已准备"状态
   - 其他玩家的标签页也能看到状态更新

#### 测试 5: 聊天功能
1. 点击右侧聊天图标打开聊天面板
2. 输入消息并发送
3. **预期结果**: 
   - 消息显示在聊天面板中
   - 其他玩家的标签页也能收到消息

#### 测试 6: 快捷短语
1. 打开聊天面板
2. 点击表情图标
3. 选择快捷短语（例如："你好！"）
4. **预期结果**: 快捷短语作为消息发送

#### 测试 7: 离开房间
1. 在房间页面点击"离开房间"
2. **预期结果**: 返回大厅页面

#### 测试 8: 主题切换
1. 点击右上角的主题切换按钮
2. **预期结果**: 界面在浅色/深色模式之间切换

## 高级测试场景

### 场景 1: 三人斗地主房间
1. 打开三个浏览器标签页
2. 每个标签页用不同昵称连接
3. 第一个玩家创建斗地主房间
4. 其他两个玩家加入
5. 所有玩家点击准备
6. **预期结果**: 
   - 房间显示 3/3 人
   - 所有玩家准备后显示"游戏即将开始"

### 场景 2: 房间列表筛选
1. 创建多个不同类型的房间
2. 使用游戏类型筛选器
3. 使用状态筛选器
4. **预期结果**: 房间列表根据筛选条件更新

### 场景 3: 通过房间号加入
1. 创建一个房间并记下房间号
2. 在另一个标签页点击"加入房间"
3. 输入房间号
4. 点击"加入"
5. **预期结果**: 成功加入指定房间

### 场景 4: 房间已满
1. 创建一个斗地主房间（最多3人）
2. 用三个标签页加入
3. 用第四个标签页尝试加入
4. **预期结果**: 显示"房间已满"，无法加入

### 场景 5: 断线重连
1. 连接并加入房间
2. 关闭浏览器标签页
3. 重新打开并连接
4. **预期结果**: 
   - WebSocket 自动重连
   - 可以重新加入房间

## 错误处理测试

### 测试 1: 无效昵称
1. 输入空昵称或超过 20 字符
2. 点击"进入大厅"
3. **预期结果**: 显示错误提示

### 测试 2: 后端未启动
1. 停止后端服务器
2. 尝试连接
3. **预期结果**: 显示连接失败错误

### 测试 3: 加入不存在的房间
1. 点击"加入房间"
2. 输入不存在的房间号
3. **预期结果**: 显示错误提示

## 调试技巧

### 查看 WebSocket 消息
打开浏览器开发者工具 → Network → WS → 选择连接 → Messages

### 查看 Zustand Store 状态
安装 Redux DevTools 扩展，可以查看所有 store 的状态变化

### 查看控制台日志
所有 WebSocket 事件都会在控制台输出日志，格式：`[WebSocket] ...`
